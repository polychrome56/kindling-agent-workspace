# 使用代码索引

1. 确认用户选定的业务版本、仓库根目录和待处理符号，避免把根目录、4.1.0 与历史来源版本的同名函数混在一起。
2. 检查 Serena MCP 是否真的可用，并激活当前工作区。仅存在配置文件不等于工具已连接；未连接时说明需要安装/重启，不伪造查询结果。
3. 查看文件符号概览，按符号查定义、读取函数体，查询引用/调用关系。工具名称以当前 MCP 实际暴露的能力为准（tools 模式或 REPL 模式）。
4. 阅读调用者及初始化代码后再判断行为；不要从名字猜用途。结构字段变更要核对所有赋值，尤其是默认初始化与停止采集路径。
5. 对不在编译数据库内、宏禁用、Lua 注册、CGO 跨语言边界或其他版本的代码做定向文本补查；零引用不是可删除的证明。
6. 修改后重新查询受影响符号，并审查完整 diff。按用户约定做静态检查或验证，不自行扩大测试范围。

## 索引准备

本项目使用 Serena MCP，C/C++ 后端为 clangd，Go 后端为 gopls。安装及 MCP 接入见 [docs/codex/README.md](../../../docs/codex/README.md)。

- 首次运行 `bash scripts/codex/setup.sh`；依赖和缓存只写入忽略的 `.local/codex/`。
- C/C++ 使用根目录本机生成的 `compile_commands.json`；构建参数变更后重新导出。
- `export_compile_commands.py` 只导出已有 CMake/Ninja 编译命令，不构建、不伪造缺失依赖。覆盖报告中的 Lua/BPF 缺口必须说明。
- 不扫描所有历史版本；用 `.serena/project.local.yml` 指定本地 `ls_workspace_folders`，不要提交绝对路径。
- `project index` 是可选预热；索引应使用当前文件，不把历史缓存当成最新事实。

索引负责更准确地定位代码，不能替代阅读控制流、检查配置默认值和审查变更语义。
